# Аудит пакетного ввода и CSV-импорта

Дата ревизии: 24 августа 2026 года.

Статус: ✅ реализовано 24 августа 2026 года. Документ сохраняет исходные находки,
принятый контракт, выполненный порядок внедрения и regression-матрицу. Раздел 2
описывает прежнюю реализацию на момент аудита; фактический пользовательский контракт
после исправления приведён в разделах 4–6.

Результат реализации: единое mode-aware ядро имеет 100% statement/branch coverage в
изолированном прогоне; обычный и Advanced CSV прошли server/browser round-trip,
Advanced export сохраняет пять полей, а import связан с конкретным preview HMAC-токеном.

## 1. Назначение

Пакетный ввод и CSV решают разные задачи.

- **Пакетный ввод** — быстрый ручной способ добавить несколько простых карточек прямо
  в браузере. Он может иметь ограничения на многострочный контент, но обязан явно их
  показывать и не портить обратные слэши.
- **CSV для обычной колоды** — табличный обмен секцией, лицом и оборотом.
- **CSV для Advanced-колоды** — lossless-контракт компоновки. Пользователь готовит в
  другой программе или нейросети готовые значения всех полей карточки, проверяет их в
  приложении и добавляет в уже существующую Advanced-колоду.

CSV импортирует **строки карточек в выбранную колоду**. Он не создаёт колоду и не
переносит её тип, raw-оболочки, историю доверия, оформление, профиль принтера или
параметры печати. Для полного переноса колоды предназначен versioned JSON.

Пользовательские произвольные поля не входят в эту работу. Они отложены в icebox до
подтверждения спроса. Формат Advanced CSV ограничен уже существующей моделью карточки:
`section`, `front`, `back`, `upper_header`, `lower_header`.

## 2. Проверенное текущее устройство

### 2.1. Пакетный ввод

Один и тот же экран и parser используются для обычной и Advanced-колоды. Каждая
физическая строка textarea считается карточкой, первое неэкранированное `||` отделяет
лицо от оборота, а одна общая секция назначается всей пачке.

Сейчас parser:

- удаляет внешние пробелы у строки и обеих сторон;
- заменяет `\||` на буквальное `||`;
- заменяет каждую пару обратных слэшей `\\` одним обратным слэшем;
- не поддерживает верхний и нижний колонтитулы карточки;
- не формирует preview и практически не сообщает ошибок отдельных строк;
- проверяет лимит колоды до записи всей пачки, поэтому превышение quota атомарно.

### 2.2. CSV

Один parser также используется для обоих типов колод. Он декодирует только
UTF-8/UTF-8-BOM, принимает запятую, точку с запятой или tab и трактует строки так:

- две колонки — `front`, `back`;
- три колонки — `section`, `front`, `back`;
- больше трёх — отклонение строки;
- одна колонка — `front` с пустым `back`;
- checkbox «Первая строка — заголовок» просто пропускает первую строку, но не проверяет
  имена, порядок или дубликаты колонок.

Preview ничего не записывает. Непосредственный импорт повторно разбирает файл, а при
наличии отклонённых строк или превышении лимита не записывает ни одной карточки. Это
правильная основа, которую следует сохранить.

CSV-export всегда создаёт UTF-8-BOM файл с разделителем `;` и заголовком
`section;front;back`. В Advanced-колоде он теряет `upper_header` и `lower_header`.
Versioned JSON эти значения сохраняет.

## 3. Обнаруженные проблемы

### P0 — риск незаметного повреждения raw-контента

| ID | Наблюдение | Последствие |
|---|---|---|
| `BUG-IMPORT-RAW-001` | Bulk превращает каждую пару `\\` в один `\`. | Команда переноса строки и другие готовые LaTeX-фрагменты меняются до сохранения. |
| `BUG-IMPORT-RAW-002` | CSV вызывает `strip()` для каждой ячейки. | Значимые начальные/конечные пробелы и переводы строк raw-поля теряются. |
| `BUG-IMPORT-RAW-003` | Advanced CSV допускает только две/три колонки, а export содержит только три. | Значения верхнего/нижнего колонтитула нельзя импортировать; export Advanced-карточек не является round-trip. |
| `BUG-IMPORT-RAW-004` | `csv.reader` работает без strict mode. Незакрытая кавычка была принята как одноколоночное лицо. | Синтаксически повреждённый файл может выглядеть как успешный импорт с другим содержимым. |

### P1 — двусмысленный контракт и слабая валидация

| ID | Наблюдение | Последствие |
|---|---|---|
| `BUG-IMPORT-SCHEMA-001` | Header checkbox слепо удаляет первую строку. | Опечатка, иной порядок, дубликат или неизвестная колонка не обнаруживаются. |
| `BUG-IMPORT-SCHEMA-002` | Один файл может смешивать строки из двух и трёх колонок; одна колонка тоже принимается. | Случайный delimiter или лишняя ячейка незаметно меняет назначение колонок. |
| `BUG-IMPORT-DIALECT-001` | При неудаче `Sniffer` выбирается самый частый delimiter; при равенстве фактически побеждает запятая. | Неоднозначный файл может импортироваться как одноколоночные карточки вместо ошибки. |
| `BUG-IMPORT-EMPTY-001` | Полностью пустой файл и строки только с секцией дают ноль карточек без диагностической ошибки. Bulk принимает строку `||` как пустую карточку. | Пользователь получает неясный «успех» либо засоряет колоду пустой записью. |
| `BUG-IMPORT-MODE-001` | UI, подсказка и parser одинаковы в обычной и Advanced-колоде. | Advanced-поля недоступны, а safe-ориентированная инструкция создаёт ложное ожидание сохранности TeX. |
| `BUG-IMPORT-PREVIEW-001` | Preview скрывает причины отклонения, значения колонтитулов и признак усечения списка. | До записи невозможно проверить реальное сопоставление полей и найти плохую строку. |
| `BUG-IMPORT-PREVIEW-002` | Импорт можно нажать без preview; изменение файла или опций не инвалидирует старый результат. | Пользователь не обязан увидеть интерпретацию внешнего/сгенерированного файла. Серверная атомарность сохраняется, но UX небезопасен. |

### P2 — совместимость и эксплуатационные углы

- Поддерживается только UTF-8. Это хорошее безопасное значение по умолчанию, но Excel
  и старые русскоязычные источники могут дать UTF-16 BOM или Windows-1251. Кодировку
  нельзя угадывать эвристически и молча: допустим только явный allowlist.
- Не диагностируются NUL и нежелательные управляющие символы. Они должны отклоняться с
  номером строки и колонки; tab и переводы строк внутри quoted cell допустимы.
- Не показываются дубликаты уже существующих или импортируемых карточек. Их не нужно
  автоматически удалять, но preview должен предупреждать.
- Формулы электронных таблиц (`=`, `+`, `-`, `@` в начале ячейки) опасны при открытии
  CSV в spreadsheet. Канонический raw-export нельзя «лечить» добавлением апострофа:
  это нарушит round-trip. Нужны предупреждение и, только при реальном спросе,
  отдельный spreadsheet-safe export.
- HTTP-лимит 2 MiB и лимит 200 карточек существуют, но нет понятных ошибок по размеру
  отдельной ячейки и строке, которая превысила доменный лимит.

## 4. Целевой CSV-контракт

### 4.1. Канонические имена колонок

Основной режим импорта — **CSV с заголовком**. Имена стабильны, ASCII, чувствительны к
опечаткам и не зависят от языка UI. Порядок колонок произвольный.

| Тип колоды | Обязательные колонки | Необязательные колонки | Запрещённые колонки |
|---|---|---|---|
| Обычная | `front`, `back` | `section` | `upper_header`, `lower_header`, любые неизвестные |
| Advanced | `front`, `back` | `section`, `upper_header`, `lower_header` | любые неизвестные |

Экспорт обычной колоды использует порядок:

```csv
section;front;back
```

Экспорт Advanced-колоды использует порядок:

```csv
section;front;back;upper_header;lower_header
```

UI должен давать скачать пустой шаблон для текущего типа колоды. Русские aliases в
первой версии не нужны: единый машинный словарь проще объяснить нейросети и проверить.

### 4.2. Правила значений

- Значения всех ячеек сохраняются посимвольно после декодирования. Нельзя применять
  `strip()`, Unicode normalization, исправление обратных слэшей или LaTeX escaping.
- В Advanced `front`, `back`, `upper_header`, `lower_header` являются trusted raw TeX.
  `{{ card_number }}`, `{{ card_count }}`, `{{ side }}` и другие известные маркеры
  остаются буквальным текстом при импорте и раскрываются только renderer-ом.
- CSV quoting по RFC допускает delimiter, кавычки и настоящие переводы строк внутри
  поля. Это основной путь для многострочного raw-кода.
- Пустые значения разрешены. В обычной строке непустой должна быть хотя бы одна из
  `front/back`; в Advanced — хотя бы одно из `front/back/upper_header/lower_header`.
  Строка только с `section` отклоняется, а полностью пустая физическая строка
  игнорируется и учитывается в статистике как пропущенная.
- Неизвестная, дублирующаяся или пустая header-колонка, а также отсутствие обязательной
  колонки отклоняют весь файл до создания preview карточек.
- Число колонок каждой data row должно соответствовать header. Лишняя или потерянная
  завершающая ячейка — адресная ошибка, а не попытка угадать намерение.

Пример файла, подготовленного нейросетью для Advanced-колоды:

```csv
section;front;back;upper_header;lower_header
Механика;"\vfill\centering Найдите $a$\vfill";"\vfill $a=F/m$\vfill";"Механика · {{ card_number }}/{{ card_count }}";"Базовый уровень"
```

В файл переносится содержимое карточек. Оболочки `front/back` уже выбраны в целевой
колоде и могут использовать `{{ content }}`, `{{ upper_header }}` и
`{{ lower_header }}`. CSV не содержит и не утверждает эти оболочки.

### 4.3. Legacy-совместимость

Старый позиционный формат следует оставить как явно выбранный режим «Legacy без
заголовка», а не угадывать вместе с новым контрактом:

- ровно две колонки во всём файле: `front`, `back`;
- либо ровно три колонки во всём файле: `section`, `front`, `back`;
- одна ширина обязательна для всех непустых строк;
- только для обычных карточек или простого Advanced-контента без колонтитулов;
- UI предупреждает, что для полного Advanced-импорта нужен формат с заголовком.

Checkbox «первая строка — заголовок» заменяется выбором schema mode. Это убирает
ситуацию, когда первая строка данных удаляется одним ошибочным флажком.

### 4.4. Кодировка и delimiter

- Первая версия v2 обязана поддерживать UTF-8 и UTF-8-BOM.
- `;`, `,` и tab остаются разрешёнными разделителями.
- В header-режиме auto-detection сначала ищет единственное разбиение, которое даёт
  допустимые canonical header names. При нуле или нескольких вариантах просит выбрать
  delimiter, а не использует произвольный fallback.
- В legacy-режиме неоднозначный dialect также требует явного выбора.
- UTF-16LE/BE разрешается добавить следующим этапом только по BOM. Windows-1251 —
  только через явный selector. `chardet` и иное вероятностное угадывание не требуется.

## 5. Целевой пакетный ввод

Bulk остаётся быстрым ручным инструментом, но не дублирует полноценный CSV.

### Обычная колода

- одна логическая строка: `front || back`;
- общая секция пачки сохраняется;
- перед записью показываются распознанные строки и адресные ошибки;
- пустая карточка отклоняется;
- backslash всегда является обычным символом и никогда не служит escape-механизмом.

### Advanced-колода

- одна логическая строка содержит четыре поля:
  `front || back || upper_header || lower_header`;
- последние два поля могут быть пустыми; общая секция задаётся отдельно;
- поле, содержащее `||`, заключается в двойные кавычки; удвоенная кавычка означает
  буквальную кавычку. Backslash не интерпретируется;
- UI прямо предупреждает: реальный многострочный TeX и большой сгенерированный набор
  следует загружать через CSV, где стандартное quoting однозначно;
- режим preview обязателен до добавления.

Существующий escape-контракт `\||`/`\\` несовместим с lossless raw. При rollout нужен
явный legacy parser для старого ввода либо одноразовое предупреждение с preview; нельзя
молча изменить трактовку уже введённого текста.

## 6. Preview и пользовательский сценарий

1. Страница показывает формат именно текущего типа колоды и ссылку «Скачать шаблон».
2. Пользователь выбирает файл, schema mode, delimiter и при необходимости кодировку.
3. Кнопка «Проверить» разбирает файл без записи и прокручивает/focus-ит результат.
4. Preview показывает тип целевой колоды, encoding, delimiter, column mapping, число
   принятых/отклонённых/пропущенных строк и предупреждений.
5. Для каждой проблемной строки показываются физический номер, колонка, код и понятная
   причина. Усечение preview отмечается явно.
6. Для Advanced видны все пять полей. Raw отображается только как text, без HTML и без
   компиляции; длинные значения можно раскрыть.
7. Любое изменение файла или опций инвалидирует preview и снова блокирует import.
8. Advanced-import требует подтверждения «Я доверяю raw TeX из этого файла». Это не
   approval оболочки и не отменяет обязательную sandbox-компиляцию.
9. Import повторно валидирует те же байты на сервере, проверяет `expected_version` и
   quota и записывает все карточки одной транзакцией. Preview-token/fingerprint связывает
   подтверждение с конкретным файлом и опциями, но сервер не доверяет данным клиента.
10. Успешный импорт нуля карточек невозможен.

## 7. Архитектурное направление

- Ввести mode-aware `CardImportSchema`, `CardImportRow`, `ImportIssue` и
  `CardImportPreview`, не возвращать из parser временные доменные `Card` с новыми UUID
  и timestamps.
- Один чистый parser используется preview и import. Web-слой передаёт `authoring_mode`,
  выбранную схему, delimiter и encoding, но не повторяет правила колонок.
- Импорт создаёт доменные `Card` только после успешной валидации всего файла.
- CSV-export использует тот же registry колонок, что import. Это предотвращает новый
  разрыв схемы при добавлении поля.
- Ошибки имеют стабильные коды, строку и колонку; русское сообщение формируется на
  boundary. Это упрощает unit/API/E2E и будущую локализацию.
- Ограничения проверяются потоково или с жёсткими caps: размер файла, количество строк,
  длина поля и объём preview. Атомарная запись при этом сохраняется.
- Preview никогда не запускает TeX. Проверка компиляции — отдельное действие после
  импорта и всегда через существующий sandbox для Advanced.

## 9. Обязательная тестовая матрица

### Unit / parser

- safe/Advanced × header/legacy × `;`/`,`/tab;
- BOM, CRLF/LF, delimiter и кавычки внутри поля, quoted multiline;
- точное сохранение пробелов, `\`, `\\`, `%`, `{}`, `||` и UTF-8;
- literal preservation известных и неизвестных `{{ ... }}` при импорте;
- переставленные header columns; missing, duplicate, empty и unknown columns;
- одна/две/три/пять/лишние колонки, смешанная ширина, trailing empty cells;
- пустой файл, blank row, section-only, front-only, back-only и Advanced header-only;
- незакрытая кавычка, NUL/control chars, oversize field/file и слишком много строк;
- ambiguous delimiter/encoding и явные selectors;
- duplicate cards как warning без автоматического удаления.

### Round-trip

- обычный export → import сохраняет `section/front/back`;
- Advanced export → import сохраняет все пять строковых значений посимвольно;
- raw fixture включает outer whitespace, настоящие переводы строк, delimiter, кавычки,
  команды `\\`, Unicode и contextual placeholders;
- export не переносит mode/wrappers/settings, JSON переносит их и остаётся полным
  форматом колоды.

### Use case / persistence

- preview read-only;
- любая error row отклоняет весь импорт;
- quota и stale `expected_version` отклоняют весь импорт без partial rows;
- два конкурентных импорта не теряют карточки;
- UUID/timestamps создаются только при commit, порядок равен порядку data rows.

### Web / browser

- разные формы и downloadable templates для обычной и Advanced-колоды;
- подробный preview всех полей и причин, focus/scroll и явное truncation;
- изменение файла, delimiter, encoding или schema сбрасывает разрешение import;
- Advanced требует trust confirmation; safe — нет;
- E2E: внешний пятиколоночный файл → preview → import → карточки → sandbox PDF;
- E2E: malformed файл ничего не записывает и ведёт к конкретной строке;
- accessibility: keyboard-only workflow, labels, live region без потери focus.

### Security

- hostile TeX сохраняется как данные, но preview/import никогда его не исполняют;
- любой последующий Advanced preview/PDF проходит существующий sandbox и fail closed;
- сообщения не включают host paths, полный секретный контент или stack trace;
- CSV spreadsheet-formula warning не изменяет канонический raw round-trip;
- fuzz/property-набор генерирует кавычки, delimiters и переводы строк и проверяет
  export/import invariants без необязательной production-зависимости.

## 10. Definition of Done

Работа завершена, когда:

- Advanced CSV из внешней программы переносит все пять полей без изменения содержимого;
- экспортированный Advanced CSV импортируется обратно без потери полей;
- malformed/ambiguous input не может завершиться молчаливым «успехом»;
- UI до записи показывает точное mapping и каждую причину отклонения;
- preview/import используют одну спецификацию, а import остаётся атомарным;
- bulk больше не интерпретирует обратный слэш и явно ограничивает многострочный raw;
- все пункты тестовой матрицы автоматизированы, полный pytest/coverage и Chromium E2E
  проходят, а руководство и screenshots соответствуют фактическому UI.
